03 · Como funciona

Três passos, três telas.

  1. 1

    Descreva o projeto

    Um arquivo lastro.toml na raiz diz como fazer o build, que variáveis usar e em que regiões rodar.

  2. 2

    Abra um pull request

    Cada PR ganha uma URL de preview própria, comentada no próprio PR, para revisar a mudança rodando.

  3. 3

    Faça o merge

    O merge na main vai para produção. Os logs chegam ao vivo e você filtra o que importa.

    05 · Recursos

    O que vem no painel.

    • Preview por pull request

      Uma URL por PR, comentada no PR e apagada quando ele fecha.

      pr-128 pronto

    • Rollback instantâneo

      Volte para qualquer uma das últimas 20 versões sem refazer o build.

      v42 → v41

    • Logs ao vivo com filtro

      Por nível, rota, região ou texto, com retenção configurável.

      3 novas linhas

    • Build em cache

      Dependências e etapas que não mudaram são reaproveitadas entre deploys.

      cache 214/220

    • Regiões e roteamento

      Escolha as regiões; cada visitante cai na mais próxima que está saudável.

      6 de 6 ok

    • Domínios e TLS

      Aponte o domínio e o certificado é emitido e renovado sozinho.

      TLS válido

    • Variáveis por ambiente

      Segredos separados para preview e produção, cifrados em repouso.

      API_URL •••••

    • Métricas e alertas

      Requisições, erros e latência p95, com alerta quando passam do limite.

      p95 112 ms

    • CLI e API

      Tudo o que o painel faz também roda no terminal e por API.

      $ lastro rollback

    09 · FAQ

    Perguntas.

    Que frameworks a Lastro aceita?

    Qualquer projeto que gere arquivos estáticos ou rode um servidor Node. O campo framework = "auto" detecta os mais comuns; para os outros, informe o comando de build e a pasta de saída.

    Preciso do arquivo lastro.toml?

    Não para começar. Sem ele, a CLI detecta o build e usa as regiões padrão do plano. O arquivo serve para fixar essas escolhas no repositório.

    Como funciona o preview por PR?

    Cada pull request gera um deploy isolado com URL própria. O link é comentado no PR e o deploy é removido quando o PR fecha ou é mesclado.

    O rollback refaz o build?

    Não. As versões anteriores ficam guardadas prontas; o rollback só troca para onde o tráfego vai.

    Onde ficam meus dados?

    Nas regiões que você escolher no lastro.toml. Logs e métricas ficam na região principal do projeto.

    Posso usar meu próprio domínio?

    Sim, em todos os planos. Você aponta o DNS para a Lastro e o certificado TLS é emitido e renovado automaticamente.

    Como guardo segredos e variáveis?

    Pelo painel ou por lastro env set. Os valores são cifrados e separados por ambiente: preview não lê os segredos de produção.

    Posso cancelar quando quiser?

    Sim. Os planos Hobby e Time são mensais, sem fidelidade. No Empresa, vale o que estiver no contrato.
